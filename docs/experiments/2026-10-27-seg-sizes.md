# Seg model size: Nano vs Small vs Medium vs Large vs XLarge (2026-10-27)

**Question:** is RF-DETR Seg Small (v1b) the right size, or does a bigger model fit masks better
(and is a smaller one good enough for the Orin)?

**Answer:** **keep Small.** No bigger size beats it on any set; Large only ties it on our own
test meal. Nano is the only clear step down (-0.03 on meal_03). Small stays the deployed model.

## Results

Same recipe as v1b (our meals + FLIC + MFR, `AUG_CONSERVATIVE`, 50 epochs, one H100 each); only
the size changes. Cells: segm mAP50:95 / count exact (share of images where predicted food blobs
at conf >= 0.5 equal the labelled number). Sets as in
[2026-10-27-seg-v0-v1-v1b.md](2026-10-27-seg-v0-v1-v1b.md).

| Size | Input px | meal_03 test | FLIC holdout | MFR holdout | Train time |
|---|---|---|---|---|---|
| Nano | 312 | 0.853 / 82% | 0.847 / 82% | 0.866 / 79% | 41 min |
| **Small (v1b)** | 384 | **0.883** / 79% | **0.856** / 82% | **0.886** / 85% | 43 min |
| Medium | 432 | 0.869 / 79% | 0.847 / 84% | 0.871 / 82% | 58 min |
| Large | 504 | 0.883 / 82% | 0.855 / 83% | 0.878 / 79% | 64 min |
| XLarge | 624 | 0.877 / 79% | 0.856 / 81% | 0.879 / 80% | 88 min |

mAP50 (looser fit) tells the same story: meal_03 0.927 / **0.949** / 0.940 / 0.941 / 0.940.

## Why bigger doesn't help here

- The sizes have about the same number of weights (33.6-38.1 M); what grows is the input
  resolution. Our food blobs are large and simple (a few per plate), so extra pixels add little.
- The training set is small (89 own images + ~2.4 k public). Bigger inputs don't find more to
  learn from it.
- Count-exact differences (79-85%) are within noise at 33-341 images per set.

## For the edge

Higher resolution costs time on the Orin Nano roughly with pixel count (XLarge has ~2.6x the
pixels of Small). Small already runs the full Workflow in ~0.6-0.7 s per plate on the Orin
(15 W mode), so there is no reason to pay for a bigger model that isn't more accurate.

## Revisit if

- Real plates bring many small items (garnish, sauces, mixed dishes) where resolution matters.
- We get a lot more own data (hundreds of meals): re-run this sweep.

## Reproduce

On Rosie, `~/intake-train`: `sbatch training/sizes.sbatch` (array: Nano/Medium/Large/XLarge,
`SIZE` env in `train_variant.py`), then `sbatch training/eval_sizes.sbatch`. Logs:
`intake_size_289608_*.log` (training), `intake_evsz_289734.log` (scores). Weights stay on Rosie
(`runs/v1b_<size>/`), not in git.
